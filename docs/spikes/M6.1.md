# M6.1 hx-ws's errors, for chat's "Auto"

**Closes:** PLAN §14.1's "Auto … reads the `htmx:ws:error` event detail, which is **UNVERIFIED (M6)**" · **Pass
criterion:** what htmx 4.0.0's hx-ws tells a page, in chromium, webkit and firefox, when a socket can't connect and when
an open one drops, measured, so Auto can fall back to SSE after two failed connects · **Result:** PASS in chromium and
webkit here; firefox in CI, by the same spec (the dev PC can't start it) · **Date:** 2026-11-01 · **Spec:**
`e2e/tests/lab/ws-errors.spec.ts`, kept, so an htmx or a browser that changes this fails there

## Decision

**Auto counts closes, not errors.** It falls back to SSE after two `htmx:ws:close` events with no
`htmx:ws:after:connection` between them, and starts the count again on every `after:connection`. It never reads
`htmx:ws:error`'s detail: there is nothing in it to read.

## What was measured

hx-ws 4.0.0 fires `htmx:ws:error` from the socket's `error` event with `{connection, error}`, where `error` is the
browser's bare `Event`: the WebSocket API gives no reason, by design, so no browser can say "refused" or "a proxy
killed it". It fires `htmx:ws:close` from `close` with `{connection, reason: "closed", code}`, and reconnects with
its backoff.

| Case | chromium | webkit |
|---|---|---|
| can't connect (a same-origin path that answers 404 to the upgrade, as a proxy that won't pass WebSockets does) | `error` (Event), `close` 1006, on every attempt | the same |
| an open socket whose server goes (no close frame) | `close` 1006, then reconnects | `error` (Event), `close` 1006, then reconnects |
| an open socket whose server drains (SIGTERM: CI's Linux runs) | `close` 1012, then each failed reconnect as in the first row | the same |

So the error is not even sent in every case (chromium drops it for a socket that was open), and its detail is the
same Event in every case where it is: a close with no connection after the last one is the one signal every case
shares, whatever its code (1006, or the server's own 1012 when it drains). A socket to another origin is refused by the page's CSP (`connect-src 'self'`) before hx-ws sees
anything, which chat never does: its sockets are same-origin.
